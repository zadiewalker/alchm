# Semantic Authority Execution Model

## Status

`UNRESOLVED SEMANTIC TRANSITIONS REMAIN FAIL CLOSED`

This record separates bounded container mechanics from meaning-bearing
continuity behavior. It does not authorize a new reflection or progression
feature.

## Execution Boundary

| Transition | Meaning authority | Runtime state | Required evidence before enablement |
| --- | --- | --- | --- |
| Sanctuary activation | Enrollment in a fixed authored sanctuary container only | Server source exists; attestation gate denies execution | Candidate-bound runtime attestation and approved exposure decision |
| Sanctuary day advancement | Increment to the next fixed authored day only; no claim of emotional progress | Server source exists; attestation gate denies execution | Replay evidence, same-SHA deployment evidence, and approved exposure decision |
| Session linkage | Claim that a reflective session participates in continuity | Unavailable | Server validation, export/deletion coverage, and semantic review |
| Completion | Claim that the authored arc has reached completion | Unavailable | Product/clinical decision, server transition and lifecycle evidence |
| Rollback | Revision of persisted continuity | Unavailable | Explicit non-revision/replay model and rollback authority |
| Transformation state | Paid and meaning-bearing continuity | Unavailable | Entitlement, native, product/clinical, and runtime authority |
| Delayed continuity | Later reflection attached to an earlier state | Unavailable | Server persistence and privacy/lifecycle verification |

## Fail-Closed Runtime Requirements

- The client cannot write continuity records.
- Environment configuration cannot constitute runtime attestation.
- A runtime gate denial cannot fall back to a client mutation or partial
  transition.
- Unsupported semantic transitions cannot be represented through adjusted
  labels, locally fabricated linkage, or inferred progress.
- New continuity persistence cannot become available before export/deletion
  treatment is verified.

## Provenance and Evidence

Bounded source implementations stamp server transition provenance and enforce
monotonic versions. Those fields describe a source contract only. Runtime
authority additionally requires a verifier-issued attestation receipt, same-SHA
deployed Functions/rules evidence, emulator authorization evidence, and
approved lifecycle handling.

RB-017 remains open until those conditions are met or the unavailable runtime
contract is explicitly approved for release.
