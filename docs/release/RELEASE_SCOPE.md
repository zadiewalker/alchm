# ALCHM Release Scope

This file defines what may be evaluated as release authority. It does not
approve the current worktree or authorize deletion of local material.

## Canonical Candidate Inputs

A candidate may include intentionally reviewed files from:

- Root application configuration and lockfiles.
- `src/`, `public/`, and release-managed application assets.
- `functions/src/`, `functions/package.json`, `functions/package-lock.json`,
  and `functions/tsconfig.json`.
- `firestore.rules`, `storage.rules`, `firebase.json`, and approved Firebase
  indexes/configuration.
- `capacitor.config.ts` and the selected canonical `ios/App/` project only
  after source/generated drift is resolved.
- `.github/workflows/`, `scripts/`, `docs/`, `AGENTS.md`, and tests that
  implement release/integrity enforcement.

## Authority Register

| Area | Canonical authority eligible for review | Competing/non-authoritative state | Certification state |
| --- | --- | --- | --- |
| Backend source | `functions/src/` | `functions/functions/` duplicate source; `functions/lib/**` generated output | Duplicate source must remain absent; generated output is not source authority |
| Workflows | `.github/workflows/` | `.github/workflows 2/`, `.github/workflows 3/` copied workflow trees | Copied workflows must remain absent |
| Native source | `capacitor.config.ts` and selected `ios/App/` only | `ios/App 2/` copied tree; generated native output | In scope; blocked pending same-SHA sync/archive/RevenueCat evidence |
| Deployment | Intentional split: Vercel static web artifact, Firebase Functions/rules, Firebase Hosting redirect edge | Static export cannot prove server authority by itself | Blocked pending same-SHA deployment, provider-secret, rollback, and receipt evidence |

## Generated Outputs

These paths may be created by local validation or platform tooling, but they
are not deployment or certification evidence by themselves:

| Path | Source authority | Treatment |
| --- | --- | --- |
| `.next/`, `out/` | Next build from candidate SHA | Generated; do not treat as candidate identity |
| `functions/lib/functions/`, `functions/lib/src/` | `functions/src/` and imported canonical source | Generated by Functions compilation; deployment evidence must name source SHA |
| CocoaPods/native copied web output | Selected native source plus sync command | Generated; require same-SHA sync/archive evidence |

Whether generated output is committed or ignored must be decided explicitly
before candidate creation; its presence in a dirty integration worktree is not
release proof.

## Excluded From Release Authority

The following local paths cannot participate in release certification unless
separately reviewed, intentionally normalized, and incorporated into the
canonical architecture:

- `functions/functions/` duplicate backend source tree.
- `ios/App 2/` and other copied native trees.
- `alchm-clean/`, `emergency-backups/`, and `artifacts/`.
- `.github/workflows 2/` and `.github/workflows 3/`.
- Duplicate suffixed files such as `* 2.js`, `* 2.js.map`, or copied pods.

The release-scope check fails when these authority-conflicting paths are
present in the checkout. It does not delete or move them.

## Deployment Authority Selected, Evidence Pending

Current repository evidence selects an intentional split topology:

- Vercel hosts the exported Next web artifact.
- Firebase Functions own server-authoritative callable/API behavior.
- Firestore rules own authorization.
- Firebase Hosting is a redirecting edge only.
- Native release remains in scope and requires same-SHA sync/archive evidence.

Until deployed evidence is captured for an exact clean SHA, the application
remains `NOT CERTIFIED`.

`npm run check:release-authority` is diagnostic and non-mutating. Generated
output may be reported as informational, but a dirty checkout remains
certification-blocking.
